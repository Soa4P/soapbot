且新旧摘要靠字符串拼接无限增长；light 模型（摘要槽）每轮重复为已经摘要过的文本付费。
summaries 表的 window_start/window_end 列（v4 迁移建的）在引擎路径上从未被写。
压缩数据死在 trace 边界：AIResult.compression 进了 extras["ai_result"]，但
MessageTrace.to_dict 不序列化——面板上看不出「这轮压缩省了多少」。

  剥除机制保证不进 provider 载荷）；折叠候选 = 超出保留窗口且行号大于水印的消息。
  候选为空 -> 完全跳过摘要调用；有候选 -> prompt = 旧摘要文本 + 仅新切片。水印随
  save_summary 写进 window_end（首次写 window_start），latest_summary_meta 读回。
- 向后兼容：无 _id 消息回退旧的全窗口折叠；engine loader 同时接受 (summary,
  watermark) 新契约与旧的纯字符串。
