# 本仓库的写作口径（去 AI 味）

参考了 `qu-ai-wei` 等公开 skill 的**约束**，按本仓库的用途重写，见
[`reference-external-2026-11.md`](reference-external-2026-11.md) §3。这里没有「门检 /
终稿 / 打磨报告」三段式模板：仓库文档不是待发布的文章，套模板只会把 CHANGELOG 变成填充题。

## 三条不可让步的约束

1. **先做敏感信息门检。** 文本里出现密码、API key、token、私钥、会话 Cookie 时停下，
   不引用、不复述、不「先掩码再继续」。概念性讨论 `token` 这个词不算凭证。
2. **冻结信息账本再动笔。** 数字、命令、路径、版本号、状态名、归因、限定、证据强度
   都不能为了顺口而改变。不得补写事实、因果、经历或结果；不得把「不确定」写成
   「确定」，把相关性写成因果；不得从症状自行推出解决方案。
3. **不鉴定作者。** 机械排比、空洞收尾是**编辑信号**，不是「这段一定是 AI 写的」。
   也不要为了「人味」添加错别字、emoji、网语、第一人称幽默或假装的个人经历。

## 本仓库特有的写法

- **CHANGELOG 每条先写「原来错在哪」。** 只写「修复了 X」会让人以为是从零实现，
  下次仍会以同样方式漏掉；这里的缺陷多数是「组件都在、线没接」。
- **结论必须能落到一处具体改动或一条明确的「不改」。** `docs/reference-*.md` 的每条
  对照都是这个形状。没有对应改动的能力，就写「不改」，不要写「未来可以考虑」。
- **不假装修了。** 未接线的能力等于不存在；未实测的写「未验证」并附验证方法；
  未实现的写「设计，未实现」。`CONTRIBUTING.md` 与 `.github/copilot-instructions.md`
  把这条列为硬要求。
- **数字同步。** 测试数量、`progress.json`、验证矩阵、交付就绪报告四处要一致，
  `scripts/check_test_gaps.py` 会拦。改了代码没改数字，比不改数字更糟。
- **README 只有四块**：是什么、怎么跑、边界、文档索引。不写功能清单，不写宣传语。
- **表格如实标注。** ✅ / ❌ / 默认关 / 仅自动 / 未验证，是给运维看的判据，不是修辞。

## 几类无争议的填充，提交前自己扫一遍

```bash
python scripts/ai_flavor_scan.py          # 只报告，不改文件，默认退出码 0
python scripts/ai_flavor_scan.py --strict # 命中即退出 1，可用于本地自查
```

扫描器只查四种模式：空洞升华词、模糊归因、整齐收尾标签、`不是…而是…` 三连。
它**不**判断作者身份、**不**自动改写、**不**默认进 CI。命中了先看是不是真的空话，
是本仓库刻意引用的历史原文或门禁说明就保留——规则服务于判断，不替代判断。
