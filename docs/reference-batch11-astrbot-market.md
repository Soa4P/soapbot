## 二、借鉴清单（机制级设计输入，按价值排序）

### 2.1 群分析总结插件（432★，多平台）——记忆面 + 聊天存档的组合能力

机制：拉取群历史消息 → LLM 按时间线摘要 → 主动推送日报/周报。soapbot 有全部底层
件（聊天存档 L0、记忆召回、send 面、长任务登记），缺的是「**按会话聚合摘要并定期
推送**」的组合编排。设计输入：摘要产物的沉淀位置（进记忆 vs 只推送）与推送频率的
审批语义（推送=主动消息，属待拍板的写面边界）。**改编候选（下批）**。

### 2.2 万能解析器（174★）——媒体链接解析聚合

机制：识别 B 站/抖音/TikTok/小红书/快手等平台的分享链接，解析出直链视频/图集/音频
并按媒体类型发送。与 soapbot 的 bili 只读面互补（bili 面只管 B 站）——**通用链接
解析聚合**是 send_media 面的上游增强。边界约束：解析目标平台的服务条款与反爬
（soapbot 的 UA/robots 纪律适用）；直链发送走 send_media 面已有沙箱。**改编候选**。

### 2.3 主动消息（351★）/ Conversa（35★）——主动消息的"分寸"设计

机制亮点不是"能主动发"而是**发得有分寸**：上下文感知（会话沉寂多久才发）、动态
情绪、免打扰时段、频控。soapbot 的主动消息在待拍板清单（A12 三重确认边界）——
这批插件的**时段/频控/免打扰设计**正是拍板后的实现规格输入。**登记**。

### 2.4 表情包管理器（566★，191k 下载，市场头部）——表情包能力面

机制：WebUI 管理页 + 资源广场 + 语义检索 + AI 智能发送 + 会话与人格选包 + 云同步。
soapbot 的 sticker-album 已有图片相册面雏形——**表情包能力面**（多包管理/语义
检索/AI 选图发送）是它的完整形态参考。边界约束：AI 智能发送=模型选图，发送仍走
send 面审批链。**改编候选（下批）**。

### 2.5 self_learning（371★）/ livingmemory（290★）——记忆演化的两条路线

self_learning：实时消息捕获 → 多维度数据分析 → 渐进式学习 → 动态人格更新 +
社交关系网络。livingmemory：完整记忆生命周期（写入→强化→衰减→检索）。对照
soapbot：温度模型管关系、星图管召回、新鲜度衰减管淡忘——这两家的「**人格随记忆
更新**」（learning→persona 增量）与「记忆生命周期状态机」是 soapbot 记忆面的
下一段设计输入（第九批 human_like 三层人格的同源延伸）。**登记**。

### 2.6 灾害预警（86★）——多源预警推送的合规形态

机制：中国地震台网/气象局/台湾中央气象署多数据源 → 实时推送。soapbot 的定时任务
+推送组合的正当用例（公共服务数据、非骚扰性）——若主动消息拍板通过，这是首选
演示场景。**登记**。

### 2.7 世界书插件（47★）——system_prompt 注入的边界审查样本

机制：特定触发条件下将预设内容注入 system_prompt（"世界书"设定注入）。**边界
审查**：soapbot 的 prompt 权威边界（人格卡是可信 operator 输入、用户消息永不进）
与此机制正面冲突——触发条件若来自用户消息=用户间接改写 system prompt。**排除
改编，登记为边界审查反例**（与 persona-growth 的"模型可写人格"不同：世界书是
触发式注入，注入源不可信）。

### 2.8 点歌插件（194★）——音乐卡片 + 语音播放

机制：音乐平台聚合 → 卡片消息 + 语音播放（TTS 唱歌是变体）。soapbot 的 send/
send_media 面可承载；音乐源的服务条款与 VIP 绕过类实现需逐仓审查（多数直接调
第三方非官方 API——与反爬纪律冲突的逐仓排除）。**候选但需逐仓边界审查**。

## 三、排除清单（安全边界与实际问题）

| 类别/样本 | 排除理由 |
|---|---|
| **远程 SSH 执行器**（23★） | 聊天 → SSH 执行远程命令 = 跨端信任级审计明令阻断的形态（弱端输入驱动强执行端），正是 #94 收紧的同类路径。**正面排除** |
| **免费谷歌逆向生图**（67★）/ 模型竞技场（167★，免费无限调用第三方模型） | 逆向/滥用第三方服务——违反 browse 面的 robots/ToS 纪律与 egress 白名单哲学（同 Cube local-search 判例） |
| **AI 自动回帖/自动发帖/自动搬史**（搬史 590★ 等，量大） | A12 三重确认边界：自动对外发布未审批。仅登记"频控/分寸"设计（见 2.3） |
| **自迭代核心**（AI 改宿主自身功能，72★） | AI 改写宿主能力与 fail-closed/审批哲学冲突（同 admin-mode 判例：danger-full-access 类） |
| **WebUI 美化/宿主页面改写类**（调色盘/传话筒立绘等） | soapbot 的面板是宿主代码，插件无宿主页面写权限（宿主完整性边界）——机制上 AstrBot 插件可改 WebUI 本身就是 soapbot 不提供的执行面 |
| **R18/猎奇内容类** | 合规 |
| **需要付费 API/反向工程登录态类** | 实际问题：无凭据预算与合规获取路径；soapbot 凭据面（BILI_COOKIE 等）只收已声明的官方来源 |
