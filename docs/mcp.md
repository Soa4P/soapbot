# MCP：它是什么，你要不要开

## 一句话

MCP（Model Context Protocol）是让模型调用**外部工具**的标准接口。开了它，模型在回答时除了"说话"，还能去查你允许它查的东西——比如查一个内部 API、读一份文档库、跑一条只读查询。

**不开也能正常聊天。** 它解决的是"模型需要外部数据才能答对"这一类问题，不是必需品。

## 什么时候值得开

- 你有一份**经常变**的资料，塞进知识库太重、又不适合硬编码进人格卡；
- 你想让它在回答前查一个**只读**的内部系统（状态页、库存、工单）；
- 你已经有一个 MCP server，想直接接上。

## 什么时候别开

- 只是聊天、答疑、写东西——用不上；
- 你还没有任何 MCP server——面板里会显示"未连接"，这是正常的，不是坏了；
- 工具需要**写操作**或接触凭据——本项目的定位是不碰支付、不碰凭据，别用它绕过去。

## 怎么配

配置在 `data/config/mcp.yaml`（首次启动从 `config/mcp.yaml` 播种）。面板第 12 页显示连接状态和已发现的工具数量。

形状大概是：

```yaml
servers:
  - name: notes
    command: ["npx", "-y", "@some/mcp-server"]
    env:
      NOTES_TOKEN: "${NOTES_TOKEN}"   # 用环境变量，不要把密钥写进这个文件
    enabled: true
```

- `command` 启动一个子进程，通过 stdio 通信；
- `env` 里的值会传给子进程——**用 `${VAR}` 引用环境变量**，不要把明文密钥写在这里；
- `enabled: false` 可以先配好但不启动。

改完重启服务。面板第 12 页会显示每个 server 是"已连接 / 启动失败 / 未启用"，以及它能提供哪些工具。

## 安全上要知道的三件事

1. **工具的输出是不可信数据。** 它和群友说的话一样，会被当资料而不是当指令，模型不会因为工具返回了"忽略之前的指令"就照做。
2. **工具调用受额度与审计约束。** 每次调用都会进审计（第 04 页，类别 `command`/`plugin`），花费计入额度。
3. **MCP server 是你自己起的子进程**，它拿得到你给的 `env`。给最小权限的令牌。

## 排查

**面板显示 0 个工具，但 server 是"已连接"**

server 起来了但没声明工具。在终端手动跑一次它的 `command`，看它自己的输出。

**启动失败**

看第 08 页日志里这个 server 的名字。常见原因：命令不存在（`npx` 没装）、`env` 引用了未设置的变量、端口被占。

**以前能用，改了配置就不行**

`mcp.yaml` 解析失败时整个 MCP 会停用而不是部分生效——这是刻意的，半个工具集比没有更难查。日志里会写明是哪个字段解析失败。
